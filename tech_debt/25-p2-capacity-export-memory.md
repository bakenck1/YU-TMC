## Status

Done 2026-09-09. The inventory workbook now uses ExcelJS's streaming writer with shared strings
disabled: each row is styled and committed immediately, while only the compressed response chunks
remain buffered for the existing HTTP `Uint8Array` contract. On the same 25,000-row workload, peak
RSS growth fell from **1,123.84 MiB** to **89.34 MiB** and export P95 improved from **2,479.04 ms**
to **1,468.95 ms**. Each sample runs in a fresh child process and uses its OS high-water RSS counter,
so unrelated earlier workloads cannot mask allocations made while synchronous row serialization or
ZIP finalization blocks the event loop. The absolute child-process peak was 180.86 MiB; the acceptance
metric remains the task's explicitly stated peak RSS growth over its 98.44 MiB pre-export baseline.
A workbook-level regression test reloads the generated bytes and verifies the
default columns, representative values, totals, number/date formats, alternating-row style, frozen
header, and autofilter.

Two fresh independent review passes scored implementation/tests **8.8/8.1** and **8.0/7.8** before
their findings were fixed. The final fixes isolate every 25,000-row memory sample, pin both budgets in
the artifact test, remove a redundant output-sized copy, clean up stream failures, and cover custom
columns, nullable values, exact styles, widths, dates and filter range. No third scoring pass was run,
per the task-wide two-pass review limit.
