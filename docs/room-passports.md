# Паспорта кабинетов

Реализация [ТЗ](TZ-room-passports.md). Раздел: `/room-passports`.

Готовые паспорта находятся в конце списка для составителей, проверяющих и администратора. Проверяющим и администратору первыми показываются паспорта на проверке. Фильтры, включая просмотр только готовых паспортов, сохраняют своё действие.

Выбранные корпус, этаж, кабинет и статус сохраняются в адресе списка. Переход в паспорт передаёт их в ссылку «К списку паспортов»; возврат, обновление страницы и кнопка браузера «Назад» восстанавливают выбор. «Сбросить фильтры» очищает сохранённые параметры. Недоступные корпус/этаж/кабинет и зависимые от них фильтры автоматически снимаются; статус сохраняется и при пустом результате.

Кнопка удаления PDF скрыта в карточке. «Вернуть в работу» открывает форму с причиной, пояснением последствий, отменой и отдельным подтверждением. Для «Другое» нужен непустой комментарий. Сервер также требует причину возврата; она сохраняется как последнее замечание до принятия. Возврат сохраняет текущий PDF, снимает паспорт с проверки или публикации и переводит его в работу. Для публикации требуется повторная отправка и принятие.

Администратор назначает роли `passport_author` и `passport_reviewer` в существующей форме пользователя. Новые роли наследуют права и ограничения сотрудника. Общий доступ к кабинетам действует только в разделе паспортов; права на ТМЦ остаются прежними.

Один текущий PDF и его метаданные хранятся в `yu_inventory.room_passports`, связанной с существующим кабинетом. Замена и удаление выполняются в одной транзакции с изменением статуса. Публичных файлов и архива PDF нет. Загрузка проверяется PDF.js в отдельном потоке: до 20 МиБ включительно, открытие документа и содержимого каждой страницы, без пароля и выполнения скриптов. Ошибки формата, при которых библиотека подменяет повреждённое содержимое пустой страницей, также отклоняются. Ограничения потока: 30 секунд и 256 МБ памяти JavaScript.

На один процесс приложения работает не более одного PDF-парсера. Очередь ограничена тремя загрузками и 15 секундами ожидания; при перегрузке пользователь получает сообщение с предложением повторить загрузку. Слот освобождается после остановки потока.

Публикация доступна через отдельный защищённый API только для принятого PDF и пользователей с действующим доступом к кабинету. Прежняя ссылка перестаёт работать после замены, удаления или возврата в работу. Просмотр открывается в отдельной вкладке; скачивание работает через тот же API с `download=1`.

Переходы используют версию записи и транзакционную блокировку кабинета, включая первый запуск работы. Сервер повторно проверяет действующую роль и версию сессии перед изменением и чтением файла. После конфликта карточка предлагает обновить данные.

Отклонённый паспорт показывается в списке и карточке красным статусом «Отклонено». Рядом указаны следующие действия: исправить замечания, загрузить исправленный PDF и повторно отправить его на проверку. После загрузки исправления карточка напоминает об отдельной повторной отправке; последнее замечание сохраняется до принятия. В базе этому состоянию по-прежнему соответствует `needs_correction`.

Паспорт «В процессе» с сохранённым замечанием выделяется в списке меткой «Есть замечания». Причина и начало комментария видны без открытия карточки; полный текст доступен внутри. Метка описывает сохранённое замечание и не утверждает, что исправления ещё не внесены.

Уведомления используют существующие события, почтовые ящики и интерфейс уведомлений сайта. Отправка уведомляет активных проверяющих, результат — текущего отправителя на проверку. Изменение паспорта и уведомления фиксируются одной транзакцией. Повторный запрос со старой версией получает конфликт и не создаёт дополнительных уведомлений. Для паспортов не создаются задания WhatsApp или web push.

## Ввод в эксплуатацию

До запуска новой версии применить миграцию `drizzle/20261006075852_room-passports.sql` через существующий процесс `npm run db:migrate` с целевым окружением. Она добавляет роли и типы уведомлений, создаёт таблицу паспортов. Действующие QR-коды сохраняются. Миграция проверена на одноразовой локальной PostgreSQL; рабочая база при реализации не изменяется.

## Проверки

- `npm run build`, `npm run lint`, `npm run ui:check`, `npm run db:check`, `npm run docs:check`.
- `npm run test:all`: общие проверки ролей, API, модели состояния и компонентов.
- `npm run test:database:local -- room-passports.test.ts tmc-operation-repositories.test.ts`: миграция, права файлов, публикация, совместная работа, транзакции и уведомления. Без аргументов команда выполняет весь набор PostgreSQL.
- Истории `RoomPassportList`, `RoomPassportCard`, `PassportFileLinks`: все статусы, замечание, пустой список и длинное имя файла.

PDF, уже скачанный пользователем, не отзывается; каждый новый запрос к ресурсу проверяется заново.
