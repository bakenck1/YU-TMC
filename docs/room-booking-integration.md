# Запись в кабинет из QR YU Inventory

Онлайн-запись сейчас полностью скрыта с сайта, включая отметку «Скоро».
Включать её следует только после отдельного указания владельца проекта.
Подготовленный блок расположен под синей карточкой кабинета, перед паспортом
и списком имущества. Оба пути используют его одинаково: напечатанный QR
`/rooms/qr/<token>` и результат встроенного сканера `/rooms/<id>`.
На телефоне кнопка занимает всю ширину блока и имеет высоту минимум 48 px.
Тексты доступны на русском, казахском и английском.

## До запуска

В `.env.local` для разработки или в серверном runtime-окружении оставьте:

```dotenv
ROOM_BOOKING_ENABLED=false
ROOM_BOOKING_ORIGIN=
ROOM_BOOKING_SHARED_SECRET=
```

Блок «Онлайн-запись», кнопка и отметка «Скоро» не показываются.
Запросов к YU Zapis нет. Имущество и паспорт кабинета открываются как раньше.
Напечатанные QR менять не нужно.

## Включение после запуска YU Zapis

Выполняйте этот раздел только после отдельного указания владельца проекта.
Запись предназначена для определённых кабинетов: включайте публикацию
только для них в YU Zapis. Для остальных помещений блок скрыт.

1. Разверните актуальный `YU-Zapis/yu-appointments`, включая поддержку
   `GET /api/inventory?roomId=<UUID>`, на его настоящем HTTPS-домене.
   В YU Zapis задайте `APP_PUBLIC_ORIGIN` равным этому домену.
2. Задайте в YU Zapis `INVENTORY_SHARED_SECRET`: отдельный случайный секрет
   длиной от 32 символов. В Inventory задайте тот же секрет в
   `ROOM_BOOKING_SHARED_SECRET`. Это отдельный ключ; `FACILITIES_API_KEY`
   используется для импорта помещений и его не заменяет.
3. Импортируйте нужные кабинеты в YU Zapis из Inventory. Импорт сохраняет связь
   как `tmc_<UUID Inventory>`. Настройте приём: сотрудников, расписание, услуги
   и публикацию кабинета. Не включайте склады и помещения без приёма.
4. В серверном окружении Inventory задайте:

   ```dotenv
   ROOM_BOOKING_ENABLED=true
   ROOM_BOOKING_ORIGIN=https://<реальный-домен-записи>
   ROOM_BOOKING_SHARED_SECRET=<тот-же-случайный-секрет>
   ```

   Указывайте только origin без пути, query и fragment. В production разрешён
   HTTPS. Для локальной разработки разрешён HTTP на `localhost`, `127.0.0.1`
   или `[::1]`, например `http://127.0.0.1:3001`.
5. Перезапустите процессы после изменения окружения. Переменные читаются
   сервером при динамическом открытии страницы; пересборка браузерного кода
   для переключения не требуется.
6. Проверьте на реальном домене: QR опубликованного кабинета → вход в Inventory
   при необходимости → «Записаться в кабинет» → YU Zapis → гостевой вход или
   Yessenov ID → форма именно этого кабинета → выбор свободного времени.
   Отдельно проверьте телефон и QR неопубликованного кабинета.

При использовании systemd из `deploy/README.md` меняйте исходный
`/etc/yu-inventory/yu-inventory.env`, заново создавайте runtime-файл через
`deploy/prepare-runtime-env.mjs`, как описано в инструкции развёртывания,
и перезапускайте web-сервис. Одного изменения `.env.example` недостаточно.

## Поведение и границы

Inventory обращается к `/api/inventory?roomId=<UUID>` только на сервере,
с `Authorization: Bearer <ROOM_BOOKING_SHARED_SECRET>`. Секрет в браузер
не передаётся. Запросы и ответы не кэшируются; лимит ожидания — 1,5 секунды,
переходы HTTP-запроса по редиректам запрещены.

При `enabled: true` проверяется адрес из ответа: тот же настроенный origin,
корневой путь и единственный параметр `room=tmc_<UUID текущего кабинета>`.
Ссылка открывается в той же вкладке; кнопка «Назад» браузера возвращает в
Inventory. YU Zapis сохраняет выбранный кабинет при входе и самостоятельно
проверяет доступные интервалы перед созданием записи.

Неопубликованный/неимпортированный кабинет, неправильная конфигурация,
ошибка сервиса или тайм-аут скрывают блок записи. Имущество продолжает
открываться. `ROOM_BOOKING_ENABLED=false` полностью скрывает блок.

Существующие правила Inventory сохранены: до входа видна форма входа;
для кабинета без доступа — сообщение о закрытом доступе. Ссылка с ID
кабинета в этих состояниях не раскрывается. Кнопка предназначена для записи
на приём, а не для бронирования помещения целиком.

Автотесты проверяют клиент Inventory, права, состояния UI, API YU Zapis
и сохранение ссылки после входа. Настоящий production-домен, рабочий вход
Yessenov ID и физический телефон проверяются после их подключения.
