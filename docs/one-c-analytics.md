# Аналитика интеграции 1С

Раздел `/integrations/1c` доступен с прежним правом `inventory.integration.one_c.manage`.
Старый адрес `/settings/integrations/1c` перенаправляет на новый после проверки доступа.

Обзор пересчитывается при загрузке и кнопкой «Обновить». Чтение выполняется
в транзакции PostgreSQL `REPEATABLE READ READ ONLY`; импорт, карточки и сохранённые
dry-run при этом не изменяются. Источники — текущий входящий реестр ОС, действующие
строки API материалов, неархивные карточки Inventory и их идентификаторы/связи.
Исторический Excel и строки старых партий не добавляются к текущему реестру.

Показатели имеют разные единицы:

- «Всего в 1С» — сумма числа ОС и уникальных кодов МП в синхронизированных реестрах,
  в позициях, не в физических единицах. Итог доступен только при наличии обоих разделов.
  Это сумма записей двух учётных категорий, не утверждение об отсутствии одного
  физического предмета в обеих категориях.
- ОС: уникальные GUID входящего реестра, отдельно на учёте и снятые с учёта.
- Материалы: уникальные коды номенклатуры; строки остатков по складам/счетам/МОЛ
  показываются отдельно. Нулевые и отрицательные остатки не участвуют в совпадениях.
- Inventory: число карточек отдельно от суммы количества единиц в карточках.
- Пять категорий диаграммы образуют разбиение карточек: только ОС, только материалы,
  оба источника, возможные совпадения, без совпадений. Критерий проверки совпадений
  общий с существующей сверкой. Временные номера — независимый признак, не шестая категория.
- Обратная сверка: действующие ОС и положительные строки материалов без какого-либо
  кандидата в Inventory. Возможное совпадение не считается доказанным отсутствием.

Число строк выбранной партии не обозначает общее количество имущества в 1С.
Дата последнего получения не подтверждает дату полного среза или его полноту.
Пустой источник материалов показывается как «Нет данных»; ошибки чтения не заменяются
нулями. Без обоих источников общий итог отображается прочерком. При отсутствии обоих
источников диаграмма и результаты совпадений заменяются коротким пустым состоянием.
Технические пояснения о доставке API, Excel и контрольных суммах в обзоре не показываются.

Кнопка «Скачать Excel · 5 листов» вызывает защищённый
`GET /api/integrations/1c/analytics/export`. Выгрузка читает один согласованный снимок
базы тем же сервисом, что и аналитика, и не зависит от пагинации или сохранённого dry-run.
Порядок листов: «ОС», «МП», «Найдено в 1С», «Временные», «Не найдено в 1С».
ОС и МП содержат полные текущие списки, включая снятые ОС и неположительные остатки.
В найденные входят только подтверждённые совпадения, одна карточка — одна строка.
Временные включают все неархивные карточки с временным номером независимо от совпадения.
Ненайденные не включают возможные совпадения; при отсутствии обоих источников лист
остаётся пустым с пометкой «Сверка недоступна», при одном источнике указан раздел сверки.
Номера и коды сохраняются текстом; количество — числом. В каждом листе есть итоги,
фильтр и закреплённые заголовки.
Проверки файла: `tests/one-c-analytics-excel.test.ts`; проверка доступа к маршруту —
`tests/one-c-material-admin-routes.test.ts`.

Блок названий и кодов работает по всему текущему реестру ОС и МП во всех вкладках.
`GET /api/integrations/1c/enrichment` строит предложения без изменения данных;
`POST` принимает только `runId=current-registry` и просмотренный `planHash`.
Выбор партии ОС и предварительный dry-run не требуются. Сначала показываются
старые/новые названия, коды, источник (ОС/МП), ответственный и причины пропуска. По одному коду
или похожему названию карточка не изменяется: нужны полный номер или официальный
штрихкод. Общий поиск включает обычные и IT-карточки. Полный номер или штрихкод
может находиться в отдельном поле, внутри наименования или строки товара.
При отсутствии отдельных идентификаторов допускается точный полный токен
описания, равный номеру карточки или декодированному официальному штрихкоду.
Части номеров, потеря ведущих нулей, начало диапазона или суффикса не подтверждают
карточку. Противоречащие отдельные поля и явные номера внутри строки блокируют предложение.
Материалы проверяются по всем положительным остаткам кандидата, включая
МОЛ/счета, которые не попали в первичный поиск по номеру. При совпадении в обоих
разделах сохранён приоритет однозначной ОС; противоречивая ОС блокирует предложение.
Перед применением в serializable-транзакции проверяются действующий администратор,
карточки, штрихкоды, связи и текущие источники. Изменившийся план возвращает 409.
Все обновления названий/кодов и записи аудита коммитятся атомарно; повтор той же
операции возвращает сохранённый результат. Исторический путь проверки партии
сохранён для прежних экранов, но не используется общим блоком интеграции.

Назначение ответственного ограничено двумя именами из пользовательского разрешения:
«Бауыржан Анесович» и «Нурмаганбет Ермек Талантович». Источник должен указывать
одного человека, на сайте должна быть единственная подходящая активная учётная запись
с допустимой ролью. Другие сотрудники, отсутствующие или неоднозначные пользователи,
различающиеся МОЛ, списанные карточки и незавершённые передачи не меняют назначения.
При назначении закрывается прежний период, создаётся `admin_override`, сохраняется
аудит `responsibility.admin_override` в одной транзакции с изменениями карточки.
В предпросмотре показаны текущий и новый сотрудник, имя из 1С и причина сохранения
назначения. Ввод поиска автоматически выбирает «Все карточки», включая скрытые
за порцией 100 строк; затем можно сузить группу. Фильтр влияет на просмотр, а применение —
на все предложения проверенного плана.
Проверки: `tests/one-c-enrichment-full-search.test.ts`, сценарии назначений и отката
в `tests/database/one-c-material-audit.test.ts`.

Проверки: `tests/one-c-analytics.test.ts`,
`tests/components/one-c-integration-dashboard.test.tsx`, сценарии аналитики в
`tests/database/one-c-material-audit.test.ts`. В Storybook используются только
отдельные синтетические примеры, не связанные с показателями рабочего сайта.

## Обновление сервера

Ветка публикации: `codex/one-c-analytics-responsibility`, создана поверх актуального
`master`. Она не содержит локальный модуль приёма накладных или его миграции.
Команды рассчитаны на штатные пути и пользователя из `deploy/README.md`.
Выполнять после прохождения CI, из учётной записи с доступом к Git и sudo:

```bash
(
  set -euo pipefail
  cd /opt/yu-inventory/current
  git fetch origin
  git merge --ff-only origin/codex/one-c-analytics-responsibility
  sudo systemd-run --wait --pipe --collect \
    --uid=yu-inventory \
    --working-directory=/opt/yu-inventory/current \
    --property=EnvironmentFile=/etc/yu-inventory/yu-inventory.env \
    --setenv=NODE_ENV=production \
    /bin/bash -c 'set -e; npm ci --include=dev; npm run build; npm run db:migrate -- --target=production; npm run db:smoke -- --target=production'
  sudo systemctl restart yu-inventory yu-inventory-push-worker
  sudo systemctl is-active yu-inventory yu-inventory-push-worker
)
```

Файл окружения читает systemd; секреты не выводятся и не копируются в Git.
При ошибке сборки или миграции команды останавливаются до перезапуска сервисов.
После обновления проверить `/integrations/1c`, скачивание пяти листов Excel и
предпросмотр изменений по текущим реестрам ОС/МП. Совпадения и назначения
применяются только после просмотра администратором.
