# Аналитика интеграции 1С

Раздел `/integrations/1c` доступен с прежним правом `inventory.integration.one_c.manage`.
Старый адрес `/settings/integrations/1c` перенаправляет на новый после проверки доступа.

Обзор пересчитывается при загрузке и кнопкой «Обновить». Чтение выполняется
в транзакции PostgreSQL `REPEATABLE READ READ ONLY`; импорт, карточки и сохранённые
dry-run при этом не изменяются. Источники — текущий входящий реестр ОС, действующие
положительные остатки МП, все неархивные карточки Inventory и их идентификаторы/связи.
Исторический Excel и строки старых партий не добавляются к текущему реестру.

Показатели имеют разные единицы:

- «Всего активных в 1С» — сумма числа ОС на учёте и уникальных кодов МП с наличием,
  в позициях, не в физических единицах. Итог доступен только при наличии обоих разделов.
  Это сумма записей двух учётных категорий, не утверждение об отсутствии одного
  физического предмета в обеих категориях.
- ОС: уникальные GUID входящего реестра со статусом «Принято к учёту».
- Материалы: уникальные коды номенклатуры; строки остатков по складам/счетам/МОЛ
  показываются отдельно. Нулевые и отрицательные остатки не участвуют в совпадениях.
- Inventory: все неархивные карточки отдельно от суммы единиц и числа активных карточек.
- Для наличия в 1С проверяются все записи ОС, включая снятые с учёта; верхние
  карточки наличия имущества по-прежнему показывают только ОС на учёте и МП с остатком.
- Диаграмма разделяет карточки на ОС, МП (включая оба источника), временные без
  совпадения и постоянные без совпадения. Варианты без полного номера показываются
  отдельно, если такие записи есть; они не объявляются подтверждёнными автоматически.
  Временный номер найденной карточки дополнительно входит в общий счётчик временных.
- Обратная сверка: действующие ОС и положительные строки материалов без какого-либо
  кандидата в Inventory. Возможное совпадение не считается доказанным отсутствием.

Число строк выбранной партии не обозначает общее количество имущества в 1С.
Дата последнего получения не подтверждает дату полного среза или его полноту.
Пустой источник материалов показывается как «Нет данных»; ошибки чтения не заменяются
нулями. Без обоих источников общий итог отображается прочерком. При отсутствии обоих
источников диаграмма и результаты совпадений заменяются коротким пустым состоянием.
Технические пояснения о доставке API, Excel и контрольных суммах в обзоре не показываются.

Кнопка «Скачать Excel · 5 листов» вызывает защищённый
`GET /api/integrations/1c/analytics/export`. Выгрузка читает один согласованный снимок
базы тем же сервисом, что и аналитика, и не зависит от пагинации или сохранённого dry-run.
Порядок листов: «ОС», «МП», «Совпадения 1С», «Временные», «Не найдено в 1С».
ОС и МП содержат полные активные списки: ОС на учёте и МП с положительными остатками.
Во вкладке ОС можно переключиться с «На учёте» на «Все статусы» и искать по всему
текущему реестру, включая ответственного. Это не меняет показатель активных ОС.
Третий лист содержит найденные и неподтверждённые совпадения с отдельным статусом
в каждой строке и раздельными итогами. Одна карточка — одна строка. Вместе с пятым
листом и листом временных он покрывает весь неархивный Inventory.
Временные включают все неархивные карточки с временным номером независимо от совпадения.
Лист «Не найдено в 1С» и одноимённый показатель содержат только постоянные номера
без совпадений. Временные карточки без совпадений не дублируются в ненайденных.
У совпавших ОС в третьем листе сохранён фактический статус источника в 1С.
Ненайденные не включают возможные совпадения; при отсутствии обоих источников лист
остаётся пустым с пометкой «Сверка недоступна», при одном источнике указан раздел сверки.
Номера и коды сохраняются текстом; количество — числом. В каждом листе есть итоги,
фильтр и закреплённые заголовки.
Проверки файла: `tests/one-c-analytics-excel.test.ts`; проверка доступа к маршруту —
`tests/one-c-material-admin-routes.test.ts`.

Вкладка ОС показывает текущий реестр через `GET /api/integrations/1c/assets/registry`,
а не строки одной исторической партии. Вкладка МП автоматически загружает остатки
через `GET /api/integrations/1c/materials/registry`. Поиск выполняется по всему
активному реестру, включая номер/штрихкод в наименовании и ответственного.
Карточка интеграции удалена из настроек; отдельный пункт навигации сохранён.

Блок «Обновление карточек из 1С» доступен во вкладках ОС и МП с одинаковыми правами
и одной проверкой всего активного реестра ОС и МП. Переключение ОС/МП сохраняет
просмотренный план; не создаёт вторую операцию применения.
`GET /api/integrations/1c/enrichment` строит предложения без изменения данных;
`POST` принимает только `runId=current-registry` и просмотренный `planHash`.
Выбор партии ОС и предварительный dry-run не требуются. Сначала показываются
старые/новые названия, коды, цены, источник (ОС/МП), ответственный и причины пропуска. По одному коду
или похожему названию карточка не изменяется: нужны полный номер или официальный
штрихкод. Общий поиск включает обычные и IT-карточки. Полный номер или штрихкод
может находиться в отдельном поле, внутри наименования или строки товара.
При отсутствии отдельных идентификаторов допускается точный полный токен
описания, равный номеру карточки или декодированному официальному штрихкоду.
При поиске целого номера пробелы, `/`, `-` и `.` считаются вариантами оформления.
Все цифры, включая ведущие нули, сохраняются. Номер может находиться внутри
наименования; произвольное сходство слов, модель и дата не заменяют номер.
Наличие подтверждается полным номером в любом поле либо принадлежностью явно
указанному диапазону номеров. Диапазоны не разворачиваются в память; префикс и
число цифр сохраняются. Сокращённый конец диапазона (например, `050-0002060-63`)
допускается только при совпадении количества источника с длиной диапазона.
Несколько записей с одним полным номером подтверждают наличие карточки в реестре,
но не выбирают автоматически цену или ответственного. Для изменения карточки
сохраняются проверки однозначности, полного номера и противоречий отдельных полей.
Материалы проверяются по всем положительным остаткам кандидата, включая
МОЛ/счета, которые не попали в первичный поиск по номеру. При совпадении в обоих
разделах сохранён приоритет однозначной ОС; противоречивая ОС блокирует предложение.
Перед применением в serializable-транзакции проверяются действующий администратор,
карточки, штрихкоды, связи и текущие источники. Изменившийся план возвращает 409.
Все обновления названий/кодов/цен/ответственных и записи аудита коммитятся атомарно; повтор той же
операции возвращает сохранённый результат. Исторический путь проверки партии
сохранён для прежних экранов, но не используется общим блоком интеграции.

Назначение ответственного ограничено двумя именами из пользовательского разрешения:
«Бауыржан Анесович» и «Нурмаганбет Ермек Талантович». Источник должен указывать
одного человека, на сайте должна быть единственная подходящая активная учётная запись
с допустимой ролью. Другие сотрудники, отсутствующие или неоднозначные пользователи,
различающиеся МОЛ, списанные карточки и незавершённые передачи не меняют назначения.
Явные варианты ФИО: «Тынымбаев Бауыржан Анесович» и «Бауыржан Тынымбаев»;
«Нұрмағанбет Ермек Талантұлы» и «Нурмаганбет Ермек Талантулы». Совпадение
только по имени не допускается, несколько активных учётных записей блокируют назначение.
При назначении закрывается прежний период, создаётся `admin_override`, сохраняется
аудит `responsibility.admin_override` в одной транзакции с изменениями карточки.
Цена берётся из первоначальной стоимости ОС только при количестве ОС 1, либо
из учётной цены за единицу МП, одинаковой во всех положительных остатках кандидата.
Для временных карточек точный сохранённый код 1С подтверждает наличие в МП.
При одинаковом коде карточка учитывается как найденная в МП, даже без номера
или штрихкода. Общая проверка обновлений может перенести название и единую цену
из положительных остатков этого кода. Ведущие нули кода сохраняются; другие коды
не участвуют. Несколько временных карточек могут иметь один код номенклатуры.
Разные названия или GUID одного кода требуют проверки; разные цены сохраняют
текущую цену карточки. Совпадение только по коду не меняет ответственного.
Поиск полного номера также использует номер внутри названия карточки Inventory
и её действующие штрихкоды. Числовые номера сравниваются со всеми цифрами и ведущими
нулями, игнорируя пробелы и разделители `/`, `-`, `.`, `*`, `_`, `:`, `\`, `·`.
В свободном тексте необычные разделители требуют явного маркера инвентарного номера;
даты, размеры и части моделей не становятся идентификаторами. Системные YUI fallback-ID
не используются как номера имущества. Изменившиеся штрихкоды требуют нового просмотра плана.
Если 1С не передала `InitialCost`, цена ОС остаётся прежней. Пустые номера и штрихкоды
в строках МП не дают права назначать их ответственного карточке только по имени товара
или сотрудника; нужен однозначный идентификатор или подтверждённый код 1С карточки.
Остаточная стоимость не подставляется вместо цены; пропущенная, некорректная или
неоднозначная цена сохраняет прежнее значение. Изменение цены входит в аудит и хеш плана.
В предпросмотре показаны текущий и новый сотрудник, имя из 1С и причина сохранения
назначения. Ввод поиска автоматически выбирает «Все карточки», включая скрытые
за порцией 100 строк; затем можно сузить группу. Фильтр влияет на просмотр, а применение —
на все предложения проверенного плана.
Проверки: `tests/one-c-enrichment-full-search.test.ts`, сценарии назначений и отката
в `tests/database/one-c-material-audit.test.ts`.

Проверки: `tests/one-c-analytics.test.ts`,
`tests/components/one-c-integration-dashboard.test.tsx`, сценарии аналитики в
`tests/database/one-c-material-audit.test.ts`. В Storybook используются только
отдельные синтетические примеры, не связанные с показателями рабочего сайта.

## Обновление сервера

Публикуется проверенный код из `master`; локальный модуль приёма накладных
и его миграции в релиз не входят. Команды используют штатные пути из `deploy/README.md`.
Пользователь `amaterasu` может не иметь доступа к каталогу приложения: вход в него
выполняется внутри `sudo bash`, операции Git — от владельца `yu-inventory`.

```bash
sudo bash <<'DEPLOY'
set -euo pipefail
cd /opt/yu-inventory/current
sudo -u yu-inventory git fetch origin
sudo -u yu-inventory git merge --ff-only origin/master
sudo -u yu-inventory git log -1 --oneline
systemctl stop yu-inventory yu-inventory-push-worker
systemd-run --wait --pipe --collect \
  --uid=yu-inventory \
  --working-directory=/opt/yu-inventory/current \
  --property=EnvironmentFile=/etc/yu-inventory/yu-inventory.env \
  --setenv=NODE_ENV=production \
  /bin/bash -c 'set -euo pipefail; npm ci --include=dev; npm run db:migrate -- --target=production; npm run db:smoke -- --target=production; npm run build'
systemctl restart yu-inventory yu-inventory-push-worker
systemctl is-active yu-inventory yu-inventory-push-worker
DEPLOY
```

Во время сборки сайт недоступен. При ошибке команды останавливаются и сервисы
остаются остановленными до успешного завершения обновления. Файл окружения читает
systemd; секреты не выводятся и не копируются в Git.
После обновления проверить `/integrations/1c`, поиск ОС и МП, все пять листов Excel
и предпросмотр названий/кодов/цен/ответственных. Изменения применяются после просмотра
администратором. Локальный файл с пустыми источниками не содержит данные рабочего сайта;
отчёт следует скачивать из нужного окружения, по времени в имени файла.
