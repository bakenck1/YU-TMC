# Перенос разработки на другой Windows-компьютер

Код проекта хранится в GitHub, а секреты и локальная база данных передаются
отдельным приватным архивом. Никогда не добавляйте архив, `.env*`, файлы из
`.data/` или каталог локальной PostgreSQL в Git: репозиторий публичный.

## Что нужно перенести

Архив рабочего места должен содержать:

- `.env.local` и другие локальные файлы окружения;
- `.data/auth-credentials.json` и `.data/session-secret`, если они существуют;
- резервные копии из `.data/backups/`;
- локальную базу `%LOCALAPPDATA%\YUInventory\postgres-development`, если нужно
  сохранить все данные текущего компьютера.

Такой архив должен передаваться через доверенный приватный канал: например,
личный зашифрованный накопитель или приватное облачное хранилище с отдельным
доступом. Не прикладывайте его к GitHub Release и не коммитьте в репозиторий.

## Восстановление

1. Установите Node.js 24.15+ и Git.
2. Клонируйте репозиторий и установите зависимости:

   ```powershell
   git clone https://github.com/bakenck1/YU-TMC.git
   Set-Location YU-TMC
   npm ci
   ```

3. Распакуйте приватный ZIP в отдельный каталог и запустите находящийся в нём
   `restore-private.ps1`, передав путь к клону:

   ```powershell
   Set-ExecutionPolicy -Scope Process Bypass
   & "D:\Private\YU-Inventory\restore-private.ps1" -ProjectDirectory "$PWD"
   ```

   Скрипт создаёт резервные копии уже существующих файлов конфигурации. Если на
   новом компьютере уже есть локальная база, он не перезаписывает её без флага
   `-ReplaceExistingDatabase`.

4. Запустите приложение:

   ```powershell
   npm run dev
   ```

Локальный режим рассчитан на Windows x64 и использует закреплённую в проекте
версию PostgreSQL. При переносе на другую операционную систему восстанавливайте
данные из логического PostgreSQL dump, а не копированием каталога базы.
