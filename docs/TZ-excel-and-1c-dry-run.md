# Техническое задание: поиск ТМЦ по 1С и Excel в dry-run

Дата: 1 октября 2026 года. Статус: код реализован; пилот на рабочих данных выполняется после развёртывания и загрузки XLS заказчиком.

## 1. Цель

При нажатии существующей кнопки «Запустить dry-run» проверять каждый ТМЦ сайта по двум полным источникам: текущему реестру ОС 1С и разовому снимку `материалы 2026.xls`. Показывать, где предмет найден, и давать скачать тот же результат в Excel. Решение нужно для проверки до подключения новой выгрузки программистом 1С.

Excel участвует только в поиске. Его строки не создают предметы, не назначают официальные номера или штрихкоды, не связывают объекты с 1С и не попадают в план публикации ОС.

## 2. Проверенное текущее состояние

Действующий dry-run проходит по строкам выбранной партии 1С и ищет предметы сайта по GUID, коду 1С, точному инвентарному номеру и официальному штрихкоду. Название не образует автоматическую связь.
- Текущий отчёт ориентирован на строки 1С. Для требования «проверить все ТМЦ сайта» нужен дополнительный сводный результат по предметам сайта, включая те, для которых нет строки 1С.
- Файл по пути заказчика `C:\Users\Bekbolat\Downloads\Telegram Desktop\материалы 2026.xls` — бинарный XLS, один лист `Лист_1$`, размер 3 727 872 байта. Его фактический SHA-256 на 1 октября 2026 года: `77C1360B98623A06980B2B9F210AD8256A2EADC414933F7B608341992B278784`. Ранее указанный hash не соответствует этому файлу.
- Это материальная ведомость за 29 сентября 2026 года. В ней есть строки заголовков и группировок; колонка «Номенклатура» содержит описание и иногда инвентарный номер после `№`. Есть отдельные колонки «Код» и «Конечный остаток». «Код» на данном этапе для поиска не используется.
- Примеры строк: `холодильник №1350/16812 от 06.11.2025`, `ноутбук ... №1350-00065`, `холодильник №206/1832-1837`. Номера повторяются, иногда у разных названий. Поэтому количество строк файла нельзя считать количеством уникальных ТМЦ.
- Заказчик сообщил текущие ориентиры сайта: 1 242 ТМЦ, в том числе 208 ОС, 450 с временным номером и 580 пока не найденных. При запуске получать фактические числа из базы, не фиксировать эти значения в коде.

## 3. Источники и загрузка файла

1. Сохранить нынешнюю интеграцию 1С и её правила сопоставления, анализа, утверждения и публикации.
2. Администратор самостоятельно загружает XLS на экране `/settings/integrations/1c`. Локальный путь на компьютере заказчика не является доступным серверу источником до этой загрузки. Каждый новый файл сохраняется как частный неизменяемый снимок; выбранный снимок используется следующим dry-run.
3. При загрузке снимка фиксировать имя, вычисленный SHA-256, размер, дату загрузки и число принятых и пропущенных строк. Показывать фактический hash на экране; не ограничивать загрузку старым hash из предыдущей версии ТЗ.
4. Читать XLS на сервере без запуска макросов и вычисления формул. Не размещать исходный файл в публичной папке сайта или в Git. Доступ к снимку и результатам дать только пользователям, которым уже разрешена административная сверка 1С.
5. Строки Excel без извлекаемого инвентарного номера пропускать для сопоставления. Весь лист всё равно просматривать: не ограничивать поиск видимой страницей, остатком или первыми строками.

## 4. Извлечение и сравнение номера из Excel

1. Искать инвентарный номер внутри колонки «Номенклатура» после знака `№`, в том числе после текста `инв.`. Отделять номер от даты, описания и следующих слов. Примеры: из `холодильник №1350/16812 от 06.11.2025` извлечь `1350/16812`; из `ноутбук ... №1350-00065` извлечь `1350-00065`.
2. Знак `№` не является частью номера для сравнения с сайтом. Сравнивать извлечённое значение с официальным инвентарным номером ТМЦ и с действующим официальным штрихкодом, если тот представляет тот же номер. Использовать существующие функции нормализации инвентарного номера и Code 39. Не удалять значимые символы `/`, `-`, внутренние пробелы или ведущие нули ради автоматического совпадения.
3. Для записи диапазона `№206/1832-1837` использовать только первый номер `206/1832`. Номера `206/1833`–`206/1837` из этой строки не выводить. Самостоятельный номер `№1350-00065` сохранять целиком; дефис в нём не означает диапазон.
4. Не искать по колонке Excel «Код» и не засчитывать совпадение по одному названию. Название использовать только для выбора строки отображения, когда одинаковый номер встретился несколько раз.
5. Совпадением считать только точный нормализованный номер. Не считать совпадением вхождение подстроки, например `206/1832` внутри другого самостоятельного номера.

## 5. Работа dry-run

1. Нажатие существующей кнопки запускает нынешний анализ выбранной партии 1С и дополнительную сверку всех ТМЦ сайта с полным снимком Excel и доступными данными 1С. Сводный результат строится **по ТМЦ сайта**: одна строка на предмет.
2. Для каждой строки показать один из итогов: «Найдено совпадение» с источником `1С`, `Excel` либо `1С + Excel`; «Не найдено»; «Временный номер — требуется проверка». Последний итог также входит в общий счётчик ненайденных.
3. Если предмет есть в обоих источниках, показывать его один раз и отмечать оба источника. Сохранять ссылки и исходные значения обеих найденных записей.
4. Наличие строки 1С считается находкой даже при статусе «Снято с учёта» или «Не в учёте». Наличие строки Excel считается находкой и при нулевом конечном остатке. Статус 1С и остаток Excel показывать отдельно и не выдавать их за подтверждение физического наличия предмета.
5. Если номер временный (`TMP-...`) и точного совпадения с источниками нет, показывать отдельный итог «Временный номер — требуется проверка», включённый в «Не найдено». Не пытаться заменить временный номер номером Excel автоматически.
6. Если номер Excel повторяется, считать предмет найденным. Показать все подходящие строки и автоматически выделить основной строкой ту, чьё название ближе к названию ТМЦ сайта. При равенстве выбирать строку детерминированно по порядку в исходном листе. Этот выбор служит только отображению: не создаёт связи и не скрывает остальные строки.
7. Если у ТМЦ нет совпадений ни в одном источнике, показать «Не найдено». Строки Excel без номера не должны превращаться в совпадения через название или код.
8. Повторный dry-run с теми же версиями источников и предметов должен давать тот же итог. В результате указывать hash Excel-снимка, идентификатор и версию партии 1С, дату и время запуска.

## 6. Экран и скачиваемый результат

- Расширить текущий экран dry-run сводкой по всем ТМЦ сайта: всего, найдено только в 1С, найдено только в Excel, найдено в обоих, не найдено, из них с временным номером. Сумма взаимно исключающих категорий должна равняться количеству проверенных ТМЦ.
- В таблице оставить привычный статус «Найдено совпадение», добавить источник, номер сайта, извлечённый номер Excel, номенклатуру Excel, статус 1С, конечный остаток Excel и ссылки на предмет/запись. При нескольких строках Excel дать открыть все варианты и увидеть автоматически выделенный.
- Сохранять фильтры, поиск и серверную пагинацию. Показывать все строки результата через страницы, не отправлять весь реестр в браузер одним ответом.
- Дать скачать Excel-отчёт именно по итогам нового общего dry-run. В отчёте одна основная строка на ТМЦ с теми же итогами и источниками, что на экране; повторяющиеся строки Excel приложить отдельным листом или отдельными строками деталей с явной связью с ТМЦ. Сохранить действующую выгрузку исходных строк партии 1С, чтобы не менять её смысл.
- Экспорт экранирует ячейки из внешних источников как текст, не создаёт формулы из строк XLS и не содержит ключей интеграции, скрытых полей или исходного файла целиком.

## 7. Границы безопасности и совместимости

- Дополнительная Excel-сверка читает данные ТМЦ и снимок источника. Она не пишет в `items`, `barcode_registry`, `item_one_c_links`, историю операций или решения администратора.
- Совпадение Excel не меняет предложенное действие существующего плана 1С (`create`, `link`, `update`, `exclude`) и не открывает возможность утвердить или опубликовать строку 1С, которую нынешние правила блокируют. Ошибка XLS-сверки показывается явно и не должна превращаться в разрешённую публикацию.
- Участие 1С в сводном поиске не отменяет текущих проверок конфликтов GUID, номеров, штрихкодов, версий и бухгалтерских статусов при публикации.
- Отчёт о совпадениях не утверждает, что предмет физически найден при обходе: это совпадение учётных данных.

## 8. Проверка готовности

1. При подготовленном снимке dry-run охватывает все текущие ТМЦ сайта и полный реестр источников; количество строк сводки и сумма категорий совпадают с фактическим количеством ТМЦ.
2. `холодильник №1350/16812 от 06.11.2025` находится по номеру сайта `1350/16812`; в сравнении не требуется знак `№`.
3. `№206/1832-1837` находит `206/1832`, но не создаёт находку для `206/1833`; `№1350-00065` не обрезается до `1350`.
4. Строка Excel без инвентарного номера не даёт совпадение по названию или коду. ТМЦ, которого нет и в 1С, получает «Не найдено».
5. Повтор номера у разных названий даёт «Найдено», показывает все строки и детерминированно выделяет наиболее похожую; выбранная строка не меняет ТМЦ.
6. Совпадение в обоих источниках создаёт одну строку ТМЦ с двумя отметками. Списанное ОС 1С и строка Excel с нулевым остатком остаются находками с явным указанием этих фактов.
7. Временный ТМЦ без точного совпадения показан отдельно и входит в «Не найдено».
8. Содержимое скачанного отчёта соответствует экрану и включает hash XLS и версию партии 1С. После dry-run данные ТМЦ остаются прежними, а план публикации 1С рассчитывается по действующим правилам независимо от Excel.

## 9. Последовательность реализации

1. Проверить XLS и дать администратору загрузить неизменяемый снимок с вычислением SHA-256.
2. Добавить разбор инвентарных номеров и индекс для точного поиска по снимку.
3. Построить отдельную сводку по ТМЦ при действующей кнопке dry-run, затем экран и скачиваемый отчёт.
4. Проверить примеры выше и запустить пилот на реальных данных без публикации предметов.

Позднее можно добавить регулярную загрузку файла или заменить его полноценной передачей номенклатуры из 1С. Это отдельная задача; текущий снимок и логика поиска должны оставаться проверяемыми по hash.
