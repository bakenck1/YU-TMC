# API обмена основными средствами с 1С

Версия контракта: 1.0
Дата: 7 сентября 2026 года

## Назначение

Сервис принимает сведения об основных средствах из 1С в формате XML. Каждая
запись идентифицируется постоянным GUID объекта 1С. Повторная отправка разрешена:
новая запись создаётся, изменённая обновляется, полностью совпадающая отмечается
как `unchanged`.

Сейчас endpoint доступен только из внутренней сети Yessenov University. Код
отправки может быть разработан и проверен на локальном mock-сервисе, а итоговый
тест должен выполняться с сервера 1С или компьютера внутри университетской сети.

## Endpoint

```http
POST https://inventory.yu.edu.kz/api/integrations/1c/fixed-assets
Authorization: Bearer <API_KEY>
Content-Type: application/xml; charset=utf-8
```

- Максимальный размер тела запроса: 10 MiB.
- Максимальное количество записей в одном запросе: 5000.
- Кодировка XML: UTF-8.
- `GET` по этому же URL описывает capability и наличие настройки ключа, но не
  проверяет доступность базы данных и не загружает данные.
- API-ключ передаётся отдельно от документации и не должен публиковаться в группе.

## Структура XML

Корневой элемент — `FixedAssets` (также поддерживается существующий
`FixedAssetsExport`). Каждое основное средство передаётся отдельным элементом
`FixedAsset`. Namespace, DTD/entity и произвольные wrapper-элементы не
поддерживаются.

| XML-тег | Тип и формат | Обязательность | Назначение и правила |
|---|---|---|---|
| `GUID` | UUID, строка | Да | Постоянный GUID основного средства в 1С. Ключ создания и обновления записи. Нельзя менять после первой отправки. |
| `Code` | Строка, до 255 символов | Условно | Код основного средства в 1С. Обязателен, если не передан `Name`. Рекомендуется передавать всегда. |
| `InventoryNumber` | Строка, до 255 символов | Нет | Инвентарный номер. Если в 1С это отдельное значение, его следует передавать отдельно от `Code`. |
| `Name` | Строка, до 255 символов | Условно | Наименование основного средства. Если отсутствует, `Code` используется для временного технического наименования. Рекомендуется передавать всегда. |
| `Category` | Строка, до 255 символов | Нет | Категория, тип или группа учёта основного средства. |
| `Barcode` | Строка, до 255 символов | Нет | Штрихкод. Поскольку штрихкоды в текущей базе 1С не используются, тег можно не передавать или отправлять как `<Barcode/>`. |
| `ResidualValue` | Неотрицательное число | Нет | Остаточная стоимость. Предпочтительный формат — `12544.50`; также принимается `12544,50`. Валюта по текущему контракту — тенге. |
| `Status` | Строка | Рекомендуется | Состояние учёта. Согласованные значения: `Принято к учёту`, `Снято с учёта`, `Не в учёте`. |
| `Location` | Строка, до 255 символов | Нет | Подразделение или местонахождение из регистра сведений 1С. |
| `Responsible` | Строка, до 255 символов | Нет | ФИО материально ответственного лица для отображения. Не используется как постоянный идентификатор. |
| `ResponsibleGUID` | UUID, строка | Нет | Постоянный GUID физического лица или связанного объекта 1С. Предпочтительный ключ для связи с ответственным сотрудником. |
| `Quantity` | Неотрицательное число | Нет | Количество. Если тег отсутствует, принимается значение `1`. Для индивидуального ОС рекомендуется `1`. |
| `AcceptedAt` | Дата `YYYY-MM-DD` | Нет | Дата принятия к учёту. Также принимается формат `DD.MM.YYYY`. |
| `UpdatedAt` | Дата или дата-время ISO 8601 | Нет | Дата последнего изменения записи в 1С. Например `2026-09-07T10:30:00+05:00`. |

Минимально сервер требует:

1. корректный `GUID`;
2. хотя бы одно из полей `Name` или `Code`.

Для полноценной интеграции рекомендуется всегда передавать `GUID`, `Code`,
`InventoryNumber`, `Name`, `ResidualValue`, `Status`, `Location`, `Responsible`,
`ResponsibleGUID`, `Quantity` и `UpdatedAt`.

## Пример запроса

```xml
<?xml version="1.0" encoding="UTF-8"?>
<FixedAssets>
  <FixedAsset>
    <GUID>eba5b834-db3b-11f0-a26e-7cc25579bdd7</GUID>
    <Code>000009352</Code>
    <InventoryNumber>000009352</InventoryNumber>
    <Name>Компьютер офисный</Name>
    <Category>Компьютерная техника</Category>
    <Barcode/>
    <ResidualValue>12544.50</ResidualValue>
    <Status>Принято к учёту</Status>
    <Location>Административное подразделение</Location>
    <Responsible>Иванов Иван Иванович</Responsible>
    <ResponsibleGUID>82f98532-723c-11ee-8100-00155d010100</ResponsibleGUID>
    <Quantity>1</Quantity>
    <AcceptedAt>2025-11-20</AcceptedAt>
    <UpdatedAt>2026-09-07T10:30:00+05:00</UpdatedAt>
  </FixedAsset>
</FixedAssets>
```

Пример вызова:

```bash
curl --fail-with-body -X POST \
  -H "Authorization: Bearer <API_KEY>" \
  -H "Content-Type: application/xml; charset=utf-8" \
  --data-binary "@inventory.xml" \
  "https://inventory.yu.edu.kz/api/integrations/1c/fixed-assets"
```

## Успешный ответ

HTTP `200 OK`:

```json
{
  "success": true,
  "received": 1,
  "created": 1,
  "updated": 0,
  "unchanged": 0,
  "requestId": "62e1ce58-3f78-4fdb-8f46-a04700e53952"
}
```

Значения счётчиков:

- `received` — количество записей `FixedAsset` в запросе;
- `created` — количество созданных записей;
- `updated` — количество обновлённых записей с существующим `GUID`;
- `unchanged` — количество повторно полученных записей без изменений;

Импорт атомарен: сервер сначала проверяет весь XML, затем сохраняет все записи в
одной транзакции. При ошибке ни одна запись batch не сохраняется. Повторять
следует весь запрос; частичный ответ `207` не используется.

## Ошибки

| HTTP-код | Значение |
|---|---|
| `400` | Некорректный XML, отсутствуют элементы `FixedAsset`, неправильный GUID, дата, число либо обязательное поле. |
| `401` | Заголовок `Authorization` отсутствует или Bearer-ключ неверный. |
| `429` | Для этого ключа уже выполняется импорт; повторить запрос после `Retry-After`. |
| `413` | XML превышает 10 MiB. |
| `415` | `Content-Type` отличается от `application/xml` и `text/xml`. |
| `500` | Транзакция сохранения не выполнена; ответ содержит только безопасный код `store_failed` и `requestId`. |
| `503` | API-ключ не настроен (`integration_not_configured`), база недоступна (`store_unavailable`) либо превышен 30-секундный лимит чтения/транзакции (`import_timeout`); запрос следует повторить. |

Пример ошибки авторизации:

```json
{
  "error": "unauthorized"
}
```

## Правила синхронизации

- Первичная загрузка: полный перечень основных средств.
- Последующие загрузки: можно повторно отправлять полный перечень; обработка
  идемпотентна по `GUID`.
- Рекомендуемый график: автоматическая полная выгрузка один раз в сутки и
  дополнительная выгрузка по требованию. Ежемесячная выгрузка возможна, но
  изменения появятся в Inventory с задержкой до месяца.
- Отсутствие объекта в очередном XML само по себе не удаляет его из Inventory.
  Для снятого объекта нужно передать тот же `GUID` и актуальный `Status`.
- `ResponsibleGUID` используется как стабильная ссылка; ФИО передаётся отдельно
  в `Responsible` только для отображения и сверки.

## Проверка capability

```http
GET https://inventory.yu.edu.kz/api/integrations/1c/fixed-assets
```

Пример ответа:

```json
{
  "service": "1c-fixed-assets",
  "status": "capability",
  "configured": true,
  "method": "POST",
  "authentication": "Bearer token required",
  "contentType": ["application/xml", "text/xml"],
  "maximumBytes": 10485760
}
```

Этот ответ подтверждает только наличие endpoint и сообщает, настроен ли ключ.
Он не проверяет базу данных, не является описанием полей и не выполняет загрузку.
