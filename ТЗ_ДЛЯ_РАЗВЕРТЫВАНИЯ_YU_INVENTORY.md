# Техническое задание: размещение системы YU Inventory

## 1. Назначение системы

**YU Inventory** — внутренняя веб-система университета для учёта, контроля и
инвентаризации имущества и товарно-материальных ценностей (ТМЦ).

**Доменное имя:** `inventory.yu.edu.kz`.

Система работает через браузер на компьютерах и смартфонах. Доступ к ней
должен быть только по защищённому протоколу HTTPS.

## 2. Функциональное описание

Система обеспечивает:

- ведение карточек оборудования и ТМЦ: название, инвентарный номер, категория,
  кабинет, ответственный сотрудник, статус и фотография;
- создание и сканирование QR-кодов для быстрого поиска имущества;
- проведение инвентаризации по зданиям, кабинетам и сотрудникам;
- передачу имущества между сотрудниками и согласование заявок на передачу;
- создание заявок на ремонт/обслуживание с прикреплением фотографии;
- учёт списанного имущества;
- экспорт реестров и отчётов в Excel;
- аналитику по имуществу и инвентаризациям;
- разграничение прав для администратора, склада и сотрудников;
- журнал действий пользователей (аудит);
- push-уведомления по операциям с ТМЦ.

Интерфейс доступен на русском, казахском и английском языках.

## 3. Требования к серверу

Рекомендуемая конфигурация для production:

| Ресурс | Требование |
| --- | --- |
| ОС | Ubuntu Server 22.04/24.04 LTS, Linux x86_64 |
| Процессор | 4 vCPU |
| Оперативная память | 8 ГБ RAM |
| Диск | 100 ГБ SSD/NVMe |
| Резервные копии | отдельное хранилище от 100 ГБ |
| Сеть | статический публичный IP, от 100 Мбит/с |

Минимально допустимо: 2 vCPU, 4 ГБ RAM, 60 ГБ SSD — для небольшого числа
пользователей.

Фотографии хранятся в PostgreSQL, поэтому при активной загрузке фото объём
диска следует увеличивать. Одна фотография ограничена 5 МБ.

## 4. Программное обеспечение

- Node.js 24.15.x в пределах major-ветки Node 24;
- PostgreSQL 16 или новее;
- Nginx для HTTPS и обратного проксирования;
- systemd для автоматического запуска приложения и фонового push-worker.

**Docker не используется и не требуется.**

## 5. Сеть и безопасность

- Открыть снаружи только порты TCP 80 и 443.
- Приложение работает локально на `127.0.0.1:3000`; порт 3000 не открывать в интернет.
- PostgreSQL не должен быть доступен из публичного интернета.
- Настроить SSL-сертификат для `inventory.yu.edu.kz` (допускается Let's Encrypt).
- Выполнять ежедневное резервное копирование PostgreSQL и хранить копии не менее 30 дней.
- Включить мониторинг доступности сайта, свободного места на диске и состояния базы данных.

## 6. Результат работ администратора

1. Система доступна по адресу `https://inventory.yu.edu.kz`.
2. Настроены Node.js, PostgreSQL, Nginx и systemd-сервисы.
3. Применены миграции базы данных и выполнена проверка подключения.
4. Работают вход, QR-сканирование, создание ТМЦ, загрузка фото, заявки и push-уведомления.
5. Настроены автоматические резервные копии PostgreSQL.

Подробные файлы для развёртывания без Docker находятся в папке `deploy/` проекта.
